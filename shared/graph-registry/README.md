# `graph/1` 레지스트리 — 이 계층의 **단일 정본**

이 폴더가 그래프 계층의 어휘를 소유한다. 노드 종류, 각 종류가 가지는 필드,
필드 이름, 오류 코드, 저널 종류, 노드 사이를 건너는 봉투 — 전부 여기서 선언하고
**코드는 여기를 따른다**. 코드가 여기와 어긋나면 게이트가 실패한다.

## 왜 이게 있어야 하는가

정본 스펙(`docs_기획안/2026-08-03_Agentlas_graph_automation/06_Graph_Wire_Protocol_Spec_v1.md`)은
이미 완결돼 있었다. 그런데 §2.1이 요구한 **레지스트리 실물이 없어서**, 스펙을 안 읽고
구현하는 일이 실제로 일어났다:

> 2026-08-04 — 노드 간 데이터 프로토콜을 `agentlas.node-output.v1`이라는 이름으로 새로
> 만들었다. 06 §4가 이미 같은 경계를 `graph/1` 네임스페이스로 규정하고 있었고, 큰 값
> 처리는 `$blob`(자동 외부화)인데 나는 `ref` + 필드별 256KiB 상한 + 실행 실패로 만들었다.
> 06 §4.6은 **"필드 단위 문자 상한은 어디에도 없다"**고 명시한다.

문서만으로는 이 사고를 막을 수 없다. 사람이 읽어야 하기 때문이다. 레지스트리는
**게이트가 읽으므로** 안 읽고 지나갈 수 없다.

## 파일

| 파일 | 담는 것 |
|---|---|
| `blocks.json` | 빌딩블록 — 노드 종류 → 기능 → 하위 기능, 각 블록이 소유하는 필드 |
| `fields.json` | 필드 사전 — 이름·등급(critical/degradable/extension)·쓰는 자·읽는 자·미지값 처리 |
| `errors.json` | 오류 코드 단일 네임스페이스 (06 §8) |
| `journal.json` | 저널 종류와 UI 매핑 (06 §7) |
| `envelopes.json` | 경계별 봉투 — 무엇과 무엇 사이에 무엇이 오가는가 |

## 상태 표시(`status`)

레지스트리는 **지금 있는 것과 앞으로 있을 것을 섞지 않는다.** 모든 항목은 상태를 갖는다:

- `implemented` — 코드에 있고, 게이트가 코드와 대조한다
- `specified` — 06/04가 규정했지만 아직 코드에 없다. 게이트는 코드에 **없어야** 정상으로 본다
- `drift` — 코드에 있는데 정본과 어긋난다. **고쳐야 할 목록**이며 게이트가 개수를 보고한다

`specified`를 `implemented`로 옮기는 것이 구현이고, `drift`를 비우는 것이 정리다.
어느 쪽도 조용히 일어나지 않는다.

## 규칙

1. **여기 없는 어휘를 코드가 쓰면 게이트 실패.** 새 코드·새 필드·새 저널 종류는 여기 먼저.
2. **여기 있는데 코드에 없으면** `status: "specified"`여야 한다. 아니면 게이트 실패.
3. **06과 이름이 다르면 `drift`다.** 이름을 마음대로 지어 놓고 나중에 맞추지 않는다.
4. **검사 못 하면 실패.** 파일이 없거나 비어 있으면 PASS가 아니라 FAIL이다(06 §13.2).
