# 변경 영수증 (Change Receipts) — 기획서 + 기술 설계 초안

> 상태: 기획 초안 (코드 없음). 작성일 2026-07-01.
> 근거: 세 저장소(`agentlas` 웹 · `agentlas_desktop` · `Hephaestus`) 실제 코드 조사(읽기전용).

## 0. 이 문서를 쓰기 전에 확인한 현실 (근거)

기획을 추측이 아니라 실제 데이터 위에 세우기 위해 먼저 저장소를 훑었다. 요약:

| 무엇 | 지금 상태 | 근거(파일:라인) |
|---|---|---|
| **코드 변경 원천** | Git 커밋. 에이전트 귀속은 커밋 본문 `Co-Authored-By: Claude Opus 4.8 / Fable 5 …` 트레일러 | 세 레포 `git log` 전수 — agentlas 123건·desktop 52건·Hephaestus 18건 모두 트레일러 포함 |
| **DB 변경 원천(웹)** | Mongo(또는 `atlas.json` 파일) 3-백엔드. 쓰기는 `persist()`/`mongoSaveXxx()` 65+ 지점, 18+ 컬렉션 | `agentlas/AgentsAtlas/app/src/lib/store/index.ts` |
| **이미 있는 감사로그(웹)** | `accountEvents` 배열 — 주요 동작 다 기록, **최대 500개 유지** | store `accountEvents`(500 cap) |
| **천연 충돌 신호(웹)** | Mongo 문서마다 `rev`(리비전) **낙관적 잠금** — 남이 먼저 바꾸면 rev 불일치 | `persistMongo`(rev 검사) |
| **동시성 제어(웹)** | `queueWrite()`로 순차 쓰기 보장 | store `queueWrite` |
| **세션/실행 기록(데스크탑)** | `chat_messages` SQLite에 user/assistant 메시지 영구 저장(id/chat_id/role/text/created_at). 실행 이벤트는 메모리 `activeRuns`에만(최대 4000, **final/error 시 폐기**) | `electron/store/chats.ts:262`, `electron/ipc.ts:284,1336-1381` |
| **에이전트 귀속(데스크탑)** | 실행은 `Chat.agentId`로 어떤 에이전트인지 식별. 멀티에이전트 이벤트는 `agentId/agentName/role/phase/delegateTo` 포함 | `electron/mcp/client.ts:579`, `shared/types.ts:1967` |
| **생성물 이력(데스크탑)** | `agent_app_operations` / `agent_tool_operations` / `agent_surface_asset_pack_operations` 테이블에 앱/도구/화면 생성 이력 | `electron/store/agent-*.ts` (미지수 U-1) |
| **배포(웹)** | `railway` CLI가 HEAD 커밋 빌드. **앱이 "지금 배포된 커밋"을 모름** — 빌드 SHA 캡처·health의 커밋 반환 없음 | `agentlas/.../deploy/runbooks/railway.md`, health 엔드포인트 |
| **배포(데스크탑)** | `git tag v0.5.7 push` → 로컬 `package:mac`(서명·공증) → `agentlas-ai/agentlas-desktop-releases`로 발행 | `scripts/publish-mac-release.mjs` |
| **되돌리기용 이전상태** | **코드=git엔 있음. DB=없음(제자리 덮어쓰기, history 컬렉션 없음). 배포=deployment id 추적 안 함** | store(스냅샷 없음), railway(id 미추적) |

**결론 한 줄:** "누가·언제·무엇을 바꿨나"의 재료는 **세 군데에 흩어져** 이미 존재한다(git 커밋 · Mongo accountEvents · 데스크탑 operation 테이블). **없는 것은 (1) 이 셋을 하나의 사람 언어 영수증으로 묶는 층, (2) DB 되돌리기용 변경 전 스냅샷, (3) 배포 식별자 캡처, (4) 충돌 감지기** 네 가지뿐이다. 즉 "0부터"가 아니라 "흩어진 걸 모아 사람에게 보여주기"다.

## 1. 한 줄 제품 정의 · 타겟 · 가치 명제

- **제품 정의:** 여러 AI 에이전트가 내 프로덕션(코드·DB·배포)을 건드릴 때, **"무엇이 바뀌었고 · 되돌릴 수 있고 · 안전하다"를 사람 언어로 보여주는 안심 장치.** 택배 추적·은행 거래내역처럼.
- **타겟 유저:** 헤비코더가 아니다. **에이전트에게 앱을 맡기는 라이트 개발자~비개발자.** diff를 읽을 줄 모르고, 읽고 싶어하지도 않는다.
- **가치 명제:** 매출 기능이 아니라 **신뢰·이탈 방지.** "에이전트가 뭘 했는지 모르겠고 무섭다"가 이탈의 1순위다. 이 기능은 **통제감**을 팔아 그 두려움을 없앤다. — 안전은 잘 될수록 안 보이므로, **"안 보이는 안전을 눈에 보이게"** 만드는 3개 화면이 곧 제품이다.

## 2. 유저 스토리 3개

**US-1 · 활동 피드 (택배 추적)**
> 나는 앱을 에이전트에게 맡겨두는 사람이다. 아침에 앱을 열면, **어젯밤 사이 에이전트들이 내 앱에 무슨 일을 했는지** 시간순 카드로 한눈에 보고 싶다. 각 카드는 "언제 · 누가 · 뭘 바꿈 · 지금 어떻게 됨(적용됨/되돌림)"만 알려주면 된다. 파일 이름이나 코드 조각은 필요 없다. 그래서 "아, 잘 돌아가고 있구나"를 느끼고 싶다.

**US-2 · 되돌리기 (Ctrl+Z)**
> 에이전트가 방금 바꾼 게 마음에 안 든다. 나는 커밋이 뭔지, 롤백이 뭔지 모른다. **카드 옆의 큰 [되돌리기] 버튼 하나**로 "그거 하기 전으로" 돌아가고 싶다. 누르면 "되돌리는 중… → 되돌림 ✅"만 보이면 된다. 뒤에서 git이든 DB든 배포든 뭘 하는지는 몰라도 된다.

**US-3 · 충돌 경고 (평소 조용, 딱 한 번 빨강)**
> 평소엔 이 화면이 조용해야 한다(경고가 잦으면 무뎌진다). 그런데 **두 에이전트가 같은 곳을 동시에 건드리는 그 순간**, 딱 한 번 빨갛게 "⚠️ 두 에이전트가 같은 곳 작업 중 — 확인할래요?"라고 물어봐 주길 바란다. 나는 [계속] 또는 [잠깐 멈춤]만 고르면 된다. 무엇을 어떻게 합칠지는 내가 정하는 게 아니다.

## 3. 화면 3개 와이어프레임 (텍스트) — 보이는 것 / 숨기는 것

### 화면 A · 활동 피드

```
┌──────────────────────────────────────────────┐
│  내 앱에 일어난 일                              │
│                                                │
│  오늘                                          │
│  ┌────────────────────────────────────────┐  │
│  │ 🟢 2:24 PM · Codex                        │  │
│  │ 당신 앱에 3가지를 바꿨어요                  │  │
│  │ 적용됨 ✅            [ ↩ 되돌리기 ]         │  │
│  └────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────┐  │
│  │ 🟢 11:02 AM · Claude                      │  │
│  │ 마켓에 에이전트 1개를 새로 올렸어요          │  │
│  │ 적용됨 ✅            [ ↩ 되돌리기 ]         │  │
│  └────────────────────────────────────────┘  │
│  어제                                          │
│  ┌────────────────────────────────────────┐  │
│  │ ⚪ 9:41 PM · Claude                       │  │
│  │ 새 버전을 배포했어요                        │  │
│  │ 되돌림 (당신이 취소) ↩                     │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```
- **보이는 것:** 시간 · 에이전트 친근한 이름(Codex/Claude) · 사람 문장 요약("3가지를 바꿈") · 상태 뱃지(적용됨/되돌림) · 되돌리기 버튼.
- **숨기는 것(절대 노출 금지):** diff, 파일 경로, 커밋 해시, 컬렉션 이름, `rev` 번호, deployment id, packageHash. — 요약 문장은 **커밋 메시지 제목 / accountEvent / 배포 이벤트에서 뽑아 사람 문장으로 정규화**하되, 원문 배관은 접힌 채로도 노출하지 않는다.
- **자평(스크린샷 테스트):** ✅ 통과에 가깝다. 비개발자가 이 한 장을 보면 "내 앱을 누가 언제 건드렸는지 한눈에 보이네, 이거 안심된다"를 느낀다. — 단 요약 문장이 "3가지를 바꿈"처럼 **모호하면 오히려 불안**할 수 있어, 문장 카피 품질이 성패를 가른다(6절 리스크 R-4).

### 화면 B · 되돌리기

되돌리기는 **별도 화면이 아니라 카드의 버튼 + 진행 오버레이**다. 그 자체가 시각화.

```
[ ↩ 되돌리기 ] 누름
        │
        ▼
┌────────────────────────────┐      ┌────────────────────────────┐
│ 되돌리는 중…                 │  →   │ 되돌렸어요 ✅                 │
│ Codex가 2:24에 바꾼 걸        │      │ 2:24 이전 상태로 돌아갔어요    │
│ 취소하고 있어요               │      │                    [ 확인 ]  │
│ ▓▓▓▓▓░░░░  잠깐만요           │      └────────────────────────────┘
└────────────────────────────┘
```
- **보이는 것:** "되돌리는 중" → "되돌렸어요" 2단계 + 무엇을 취소하는지 사람 문장. 배포까지 되돌려야 하면 "새 버전을 다시 올리는 중(1~2분)"처럼 **소요를 정직하게**.
- **숨기는 것:** `git revert`, 역커밋 push, DB 스냅샷 복원, Railway 롤백 같은 메커니즘 전부. 실패 시에도 "되돌리지 못했어요 — Agentlas 팀에 알렸어요"처럼 **유저가 손댈 수 없는 건 유저 탓으로 만들지 않는다.**
- **되돌리기 확정 다이얼로그(선택):** 코드/배포처럼 시간이 걸리거나 다른 변경 위에 쌓인 경우만 "이 뒤에 바뀐 것도 같이 영향받을 수 있어요. 계속?" 한 줄 확인. 평소엔 바로 실행.
- **자평:** ✅ 통과. "큰 버튼 하나로 되돌린다"는 비개발자가 가장 강하게 원하는 안전망이다. Ctrl+Z 멘탈모델이 그대로 먹힌다. **3개 중 감정적 임팩트 1위** → MVP 0순위 후보(7절).

### 화면 C · 충돌 경고

```
평소: (아무것도 없음 — 활동 피드만 조용히)

충돌 순간에만, 피드 최상단에 딱 하나:
┌──────────────────────────────────────────────┐
│ ⚠️  두 에이전트가 같은 곳을 작업 중이에요         │
│ Codex와 Claude가 방금 같은 부분을 바꾸려 해요.   │
│ 그대로 두면 나중 것이 앞의 것을 덮을 수 있어요.    │
│                                                │
│        [ 그대로 진행 ]   [ 잠깐 멈추고 볼게요 ]    │
└──────────────────────────────────────────────┘
```
- **보이는 것:** 누구와 누가 · "같은 곳" · 위험 한 줄("나중 것이 앞의 것을 덮을 수 있다") · 선택지 2개.
- **숨기는 것:** 어떤 파일/문서/라인인지, merge 방법, diff. **합치는 결정을 유저에게 시키지 않는다**(merge gate·diff 뷰는 헤비코더용이라 범위 밖).
- **동작:** 완전 락이 아니라 **경고 + 확인.** "그대로 진행"=그냥 둠(나중 것이 이김, 지금과 동일). "잠깐 멈춤"=뒤늦은 에이전트 실행을 보류하고 사람이 결정할 때까지 대기. 자주 뜨면 안 되므로 **감지 문턱을 보수적으로**(6절 R-3).
- **자평:** ⚠️ 조건부 통과. 뜨는 그 순간엔 "오 이거 없었으면 큰일날 뻔"이라 임팩트가 크지만, **평소 안 보이는 게 정상**이라 "이거 필요해"를 스크린샷 한 장으로 설득하긴 화면 A·B보다 약하다. → MVP 후순위(7절).

## 4. 데이터 모델 — "변경 영수증(Change Receipt)"

핵심 설계: **코드·DB·배포 세 종류를 하나의 영수증 봉투로 통일**하고, 종류별 세부는 어댑터가 채운다. 유저에게는 봉투의 "사람 언어 필드"만 보이고, `source`·`undo`는 내부 배관이다.

### 4.1 영수증 한 건 (통일 스키마 · 사람에게 보이는 층)

```jsonc
{
  "id": "rcpt_...",                 // 고유 id
  "at": "2026-07-01T14:24:03Z",     // 언제
  "actor": {                        // 누가 — 친근한 이름만 노출
    "display": "Codex",             //   화면에 뜨는 이름 (모델 id 숨김)
    "kind": "codex|claude|desktop|hephaestus|human"
  },
  "kind": "code|db|deploy",         // 내부 분류 (유저에겐 동사로 번역)
  "summary": "당신 앱에 3가지를 바꿨어요",   // 사람 문장 (diff/경로 금지)
  "target": "당신 앱",               // 친근한 대상명 ("당신 앱"/"마켓 등록"/"배포")
  "status": "applied|reverting|reverted|failed",
  "undoable": true,                 // 되돌리기 버튼 노출 여부
  "scope": "app|marketplace|deploy" // 어느 앱/영역인지(멀티프로젝트 대비)
}
```

### 4.2 되돌리기용 내부 필드 (유저에게 절대 안 보임)

이게 통일의 어려운 부분이다. 종류마다 "이전 상태"의 정체가 다르다:

```jsonc
"source": {
  // kind=code  — git이 이미 이전 상태를 들고 있음
  "code": { "repo": "agentlas", "commit": "<sha>", "parent": "<sha>" },
  //   되돌리기 = git revert <commit> + push (자동배포면 재배포까지)

  // kind=db    — ★ 현재 저장 안 됨. 되돌리기하려면 변경 전 스냅샷을 새로 남겨야 함
  "db": {
    "collection": "manifests",
    "docId": "<id>",
    "rev": 42,                      // 낙관적 잠금 값(충돌 감지에 재사용)
    "before": { /* 변경 직전 문서 스냅샷 */ }   // ← 신규로 저장해야 하는 것
  },

  // kind=deploy — ★ 현재 배포 식별자 추적 안 됨. 캡처 필요
  "deploy": {
    "commit": "<sha>",
    "prevDeploymentId": "<railway deployment id>",  // ← 캡처 필요(미지수 U-4)
    "target": "railway|desktop-release"
  }
}
```

### 4.3 세 종류를 하나로 "통일"하는 방식

- **공통 봉투 + 3개 어댑터.** 각 어댑터는 원천을 관찰해 봉투를 만든다:
  - **코드 어댑터:** git 커밋을 원천으로. 커밋 subject → `summary`, `Co-Authored-By` → `actor`, sha → `source.code`. (post-commit 훅 또는 커밋 로그 폴링. 지금은 훅 없음 → 신규.)
  - **DB 어댑터:** 웹의 `persist()`/`accountEvents` 경유. **이미 있는 `accountEvents`(500 cap)를 영수증 원천으로 승격** + 쓰기 직전 `before` 스냅샷을 같이 남긴다.
  - **배포 어댑터:** 배포 실행 시점(웹=railway 배포, 데스크탑=publish)을 잡아 `commit`+`prevDeploymentId` 기록.
- **표시 정규화:** 세 원천의 서로 다른 원문을 `summary`/`target` 사람 문장으로 바꾸는 **번역기 한 곳**이 화면 카피 품질을 책임진다(카피가 곧 제품, R-4).
- **저장 위치(제안):** 유저별로 흩어지지 않게 **단일 영수증 스토어**. 데스크탑은 `agentlas.sqlite`에 `change_receipts` 테이블 신설, 웹은 `accountEvents`를 영수증 형태로 정규화. (교차 노출은 MVP 이후, 7절.)

### 4.4 되돌리기용으로 "무엇을 새로 저장하나" (요약)

| 종류 | 이전 상태가 지금 있나 | 되돌리기용으로 저장할 것 |
|---|---|---|
| 코드 | ✅ git이 보관 | 커밋 sha만 참조하면 됨(추가 저장 최소) |
| **DB** | ❌ 제자리 덮어쓰기 | **변경 직전 문서 `before` 스냅샷** (신규 필수) |
| **배포** | ❌ id 미추적 | **직전 deployment id + 커밋 sha** (신규 필수) |

## 5. 충돌 감지 로직 초안 — "같은 자원을 밟는다" (락이 아니라 경고)

원칙: **완전 락 금지.** 늦은 에이전트를 막지 말고, "같은 곳을 밟는 순간"에 사람에게 **경고 + 확인**만. 자주 뜨면 무뎌지므로 문턱은 보수적으로.

### 5.1 종류별 "같은 자원" 정의 + 감지 신호

| 종류 | "같은 자원" 정의 | 감지 신호(이미 있는 것 우선) | 판정 |
|---|---|---|---|
| **코드** | 두 에이전트의 진행 중 작업이 **같은 파일**(또는 짧은 창 안 같은 레포)에 손댐 | 데스크탑 `activeRuns`에 진행 중 run들이 있음(chatId/project 보유) + 각 run이 건드리는 파일 힌트. 커밋 시점엔 "최근 N분 내 다른 에이전트 커밋이 같은 파일 포함" | 겹치면 경고 |
| **DB** | 같은 `{collection, docId}`에 두 쓰기 | **Mongo `rev` 낙관적 잠금이 천연 신호** — 쓰기 때 rev 불일치 = "남이 먼저 바꿈". `queueWrite` 순차 큐에서 같은 docId 대기 감지도 가능 | rev 불일치 or 큐에 같은 docId | 경고 |
| **배포** | 짧은 창 안 두 배포 트리거(같은 서비스) | 배포 어댑터가 "직전 배포가 아직 끝나기 전 새 배포"를 감지 | 겹치면 경고 |

- **가장 확실한 즉시 승리:** **DB의 `rev` 불일치**. 이미 코드에 낙관적 잠금이 있으니, 그 불일치를 **에러로 삼키지 말고 충돌 이벤트로 승격**하면 신규 인프라 거의 없이 화면 C의 DB 케이스가 성립한다.
- **코드 충돌**은 "진행 중 두 run이 같은 파일"을 알아야 하는데, 지금 `activeRuns`엔 파일 단위 힌트가 약함(미지수 U-2) → **커밋 시점 사후 감지**(같은 파일 최근 겹침)로 시작하는 게 현실적.

### 5.2 경고 흐름(락 아님)

1. 감지 → 화면 C 배너 1회 + 해당 에이전트 run에 "사용자 확인 대기" 표식(멈춤 아님, 사람이 볼 때까지 결과 보류 옵션).
2. [그대로 진행] → 아무것도 안 막음(현재 동작 유지, 나중 것이 이김).
3. [잠깐 멈춤] → 늦은 쪽 run의 **적용을 보류**(결과를 커밋/쓰기/배포 직전에서 대기). 사람이 결정.
4. 로그: 충돌도 영수증 스토어에 `kind:"conflict"` 이벤트로 남겨 활동 피드에 흔적(선택).
- **문턱:** 같은 자원 + **시간 창**(예: 몇 분) + 서로 다른 actor. 문턱을 좁혀 오탐(피로) 최소화.

## 6. 구현 난이도 · 리스크 · 미지수 (이 저장소 현실 기준)

### 6.1 난이도(상대)

| 항목 | 난이도 | 근거 |
|---|---|---|
| 활동 피드(읽기) | **낮음** | 원천이 이미 존재(git 로그·accountEvents·operation 테이블). 모아서 사람 문장으로 정규화 + 표시만 |
| 코드 되돌리기 | **중** | `git revert`+push는 확실하나 **자동배포와 결합** → 되돌리기=역커밋+재배포(5~10분). 진행 표시·실패 처리 필요 |
| DB 되돌리기 | **중상** | 현재 **변경 전 스냅샷이 없음**. 65+ 쓰기 지점을 `persist()`/`queueWrite` 한 길목에서 잡아 `before` 저장 구조 신설. rev 낙관적 잠금과 정합 필요 |
| 배포 되돌리기 | **상/미지수** | 앱이 배포 커밋·deployment id를 모름. Railway 롤백 API/CLI 존재 여부 확인 필요(U-4). git revert 재배포가 더 안전할 수 있음 |
| 충돌 감지(DB) | **낮음** | `rev` 불일치를 충돌로 승격만 하면 됨 |
| 충돌 감지(코드) | **중** | 진행 중 run의 파일 단위 겹침 인지 필요(U-2). 사후(커밋 겹침) 감지로 시작 권장 |

### 6.2 리스크

- **R-1 (되돌리기의 되돌리기/연쇄):** A 변경 위에 B가 쌓였는데 A를 되돌리면 B가 깨질 수 있다. → 되돌리기 확정 시 "이 뒤 변경도 영향받을 수 있음" 한 줄 확인 + 코드는 git이 충돌 알려줌. DB는 `rev`가 바뀌었으면 단순 `before` 복원 대신 "지금 못 되돌려요" 안전 실패.
- **R-2 (자동배포 지연 vs 즉시성 기대):** 유저는 Ctrl+Z처럼 즉시를 기대하나 코드/배포 되돌리기는 분 단위. → 화면 B에서 소요를 정직하게. DB·간단 변경은 즉시.
- **R-3 (충돌 경고 피로):** 자주 뜨면 무시된다. → 문턱 보수적, 평소 0건이 정상.
- **R-4 (요약 카피가 곧 신뢰):** "3가지를 바꿈"이 모호하면 오히려 불안. 원천→사람 문장 번역기의 카피 품질이 제품 성패. 숨기되 모호하지 않게.
- **R-5 (부분 실패):** 되돌리기가 코드는 됐는데 배포가 안 되는 등 부분 성공. → 영수증 status를 단계로 관리(reverting→reverted/failed), 실패는 유저 탓 안 함.
- **R-6 (멀티 레포 원천 분산):** 코드는 3개 git 레포, DB는 웹, 배포는 웹/데스크탑. 한 유저의 영수증을 어디에 모을지(교차 노출)는 MVP 이후.

### 6.3 미지수 (모르면 어디를 봐야 하나)

- **U-1:** 데스크탑 `agent_app_operations`/`agent_tool_operations`/`agent_surface_asset_pack_operations`가 "누가·언제·무엇"을 충분히 담나, 이벤트 로그가 더 있나. → `electron/store/agent-surfaces.ts·agent-apps.ts·agent-tools.ts`, `store/db.ts` v17~v21 스키마.
- **U-2:** 진행 중 run이 "어떤 파일을 건드리는지" 실시간으로 알 수 있나(코드 충돌 실시간 감지 가능성). → `electron/ipc.ts`의 `activeRuns` 레코드 필드, `McpInvocationEvent`(tool 이벤트에 파일 경로 있나).
- **U-3:** 웹 프로덕션 백엔드가 `mongo`인지 `mongo_collections`인지(충돌/스냅샷 구현이 갈림). → `railway.json`/`.env.production`의 `ATLAS_STORE_BACKEND`·`MONGODB_URI`.
- **U-4:** Railway가 이전 deployment로 롤백하는 CLI/API가 있나, deployment id를 배포 시 캡처 가능한가. → Railway CLI 문서(`railway ... rollback`), `agentlas/.../deploy/runbooks/railway.md`, GitHub Actions 워크플로우.
- **U-5:** Hephaestus 라우팅/hep-call `receipt_id`가 파일·DB에 남나(지금은 메모리·비용표시용으로 보임). 남는다면 "에이전트가 무엇을 실행했나"의 추가 원천. → `electron/hephaestus/commands.ts`, `Hephaestus/schemas`, `store/db.ts`에 hephaestus 테이블 검색.
- **U-6:** `accountEvents` 500 cap 초과 시 오래된 기록 유실 — 영수증 원천으로 쓰려면 보존 정책 확인. → 웹 store `accountEvents` 트리밍 로직.
- **U-7:** `.agentlas/memory/invocation-ledger.jsonl`이 왜 거의 비었나(작동 안 하나, 다른 데 기록되나). → `agentlas_desktop/.agentlas/memory-map.json` + 렛저 기록 코드.

## 7. MVP 범위 제안 — 무엇을 먼저, 왜

**MVP = 화면 A(활동 피드) + 화면 B(되돌리기), 단 되돌리기는 "코드 + DB"만.** 화면 C(충돌)와 배포 되돌리기는 2차.

### 순서와 근거

1. **1순위: 화면 A 활동 피드 (읽기 전용).**
   - 왜: **난이도 최저 + 원천이 이미 다 있음**(git 로그·accountEvents·operation 테이블). 되돌리기 없이도 "내 앱에 무슨 일이 있었는지 보인다"만으로 즉시 안심 가치. 스크린샷 테스트 최강.
   - 범위: 세 원천 → 영수증 봉투 정규화 + 사람 문장 번역기 + 피드 UI. 되돌리기 버튼은 자리만(비활성 가능).

2. **2순위(같은 릴리스 권장): 화면 B 되돌리기 — DB부터, 그다음 코드.**
   - 왜 DB 먼저: **`rev` + `queueWrite` 길목이 한 곳**이라 `before` 스냅샷 붙이기 깔끔하고, DB 되돌리기는 재배포 없이 **즉시** → Ctrl+Z 기대에 가장 부합.
   - 코드 되돌리기: `git revert`+재배포(분 단위). 진행 표시·실패 처리 붙여 그다음.
   - **감정적 임팩트 1위**라 피드와 함께 있어야 "보고 → 되돌린다" 루프가 완성된다.

3. **3순위: 화면 C 충돌 경고 — DB `rev` 불일치 케이스부터.**
   - 왜 나중: 평소 안 보이는 게 정상이라 단독 가치 설득이 약하고, 코드 충돌 실시간 감지는 U-2 해소 필요. 대신 **DB `rev` 불일치를 충돌로 승격**하는 건 저비용이라 여기부터.

4. **4순위(별도): 배포 되돌리기.**
   - 왜 마지막: U-4(Railway 롤백) 미지수 + 자동배포 정합 리스크(R-1/R-2). 그 전까지 배포 영수증은 **표시만 하고 되돌리기는 "코드 되돌리기로 재배포" 경로로 우회**.

### MVP가 스크린샷 테스트를 통과하나 (자평)
- 화면 A: ✅ "누가 언제 내 앱 건드렸는지 한눈에" — 비개발자 즉시 공감.
- 화면 B(코드+DB): ✅ "큰 버튼으로 되돌린다" — 가장 강한 안전망, 즉시 공감.
- 두 개만으로도 **"에이전트에게 맡겨도 안 무섭다"**의 핵심(보임 + 되돌림)이 성립한다. 충돌·배포는 있으면 좋지만 없어도 MVP의 신뢰 명제는 선다.
