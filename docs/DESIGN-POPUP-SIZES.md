# 팝업 크기 체계

오너 결정 2026-08-24: **팝업1이 가장 큰 것, 팝업2는 그 가로의 70%, 팝업3은 50%.**
내용이 적은 창이 화면을 다 먹지 않게 하는 유일한 기준이다.

배경(실측): 에이전트 "도구" 창이 `size="full"` 이라 화면 전체를 차지했는데,
내용은 위 30%뿐이고 나머지는 빈 흰 바닥이었다.

## 정본

`renderer/app/globals.css`

```css
--popup-1-width: min(1040px, calc(100vw - 96px));
--popup-2-width: calc(min(1040px, calc(100vw - 96px)) * .7);   /* 728px */
--popup-3-width: calc(min(1040px, calc(100vw - 96px)) * .5);   /* 520px */
--popup-max-height: min(calc(100dvh - 48px), 880px);
```

폭을 새 숫자로 쓰지 않는다. 토큰을 고치면 모든 팝업이 함께 바뀐다.

## 무엇이 어느 크기인가 — 내용이 정한다

| 크기 | 쓰는 곳 | 기준 |
|---|---|---|
| 팝업1 | 만들기·편집 창, 게시 창, 플러그인 고르기 | 좌우 두 단이거나 목록이 길다 |
| 팝업2 | 목록·설정 시트 (`OneBottomSheet` 기본) | 한 단이고 스크롤이 생길 수 있다 |
| 팝업3 | 도구 창, 짧은 확인·입력 | 몇 줄로 끝난다 |

`OneBottomSheet` 의 `size` 는 이름을 그대로 두고 폭만 체계에 맞췄다:
`wide`/`full` = 팝업1, 기본 = 팝업2, `compact` = 팝업3.

## 모달인지 아닌지 — 딤과 role 로 가른다

화면을 덮는 딤이 있고 `role="dialog"` 가 붙었으면 모달이고, 크기 체계를
따른다. 화면 아래 떠 있는 토스트 바(`OneRecoveryPlane`), 입력창 위 말풍선
(`OneVoiceInputHelp`), 대화 안에 흐르는 블록(`OneActivityTimeline`)은 모달이
아니므로 이 체계 밖이다.

2026-08-25 감사 시점에 숫자를 직접 쓰던 모달 열한 자리를 전부 옮겼다:
묻는 시트, MCP 키 시트, 브라우저 승인 둘, 프롬프트 고르기 둘, 대여 창,
연결 창, 가져오기 창, 자격증명 창, 기능 안내 창.

## 웹으로 옮길 때

토큰 네 줄을 그대로 복사하고, 각 팝업을 위 표 기준으로 분류한다.
값을 새로 정하지 않는다 — 그러면 다시 갈라진다.
